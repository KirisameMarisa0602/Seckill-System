## 5. 死信队列防黄牛：超时废单与库存涅槃重生

为了反制黄牛下单占库存但不支付的脏套路，本系统引入了 RabbitMQ 死信队列进行彻底的延时自愈闭环。
*   设定 15 分钟（测试环境使用缩短策略）队列超时倒计时自动投递机制。
    ![rabbitmq设置15分钟付款闭锁](assets/v7.0-overall-test/rabbitmq中给订单设置15分钟付款倒计时.png)
*   超时到达，触发 RabbitMQ 转交死信通道动作，服务器开启后厨处理：退库存、去缓存限制记录等一气呵成。
    ![服务器侦听并捕捉死信执行关单预告](assets/v7.0-overall-test/15分钟超时未付款订单进入死信队列，等待服务器处理这个超时订单、补回库存、清除redis中用户：商品键值对，允许用户重新购买.png)
    ![死信队列成功接收记录信息](assets/v7.0-overall-test/超时未付款的订单进入死信队列.png)
*   **数据强力回归复发**：
    这批死信订单在底层被无情擦除并转换为 `-1` 无效状态。
    ![超时280废单设为-1状态记录](assets/v7.0-overall-test/超时的280个订单全部记录为-1（超时未付款状态）.png)
    ![数据库状态转为-1详情](assets/v7.0-overall-test/超时后订单失效，数据库中订单状态从0（待支付）变为-1.png)
    ![数据库关联记录无痕消除处理](assets/v7.0-overall-test/超时后订单失效，数据库中订单数据消失.png)
    **（最关键）系统自动补回所有损失的物理库存，且清除了 Redis 内的所有限制名单，让这批货物重见天日！**
    ![数据库实体解封库存1](assets/v7.0-overall-test/超时后订单失效，数据库中库存数量恢复.png)
    ![数据库实体解封库存回归](assets/v7.0-overall-test/超时订单处理完毕后库存回归原来的数量.png)
    ![Redis清空售罄标签开启重抢购](assets/v7.0-overall-test/超时订单处理完后redis中的售罄标志全部删除，允许用户重新购买，各类抢购商品库存与恢复到MySQL中一致.png)
